# 改这个仓之前先读这个

这份文档给**下一个要改这个仓的人或 agent**。它不列路由、不列模块、不列能力,
那种清单会漂,而漂了之后它和一份准确的清单长得一模一样。这里只放两样东西:
**不能破的不变量**,和**这个仓已经踩过的坑**。前者是设计决定,后者是事故记录,
两样都不会因为有人加了一个面板就过期。

要找清单:环境变量在 `scripts/task_console/README.md`(那张表有双向对账闸),
动作表在 `maint.py`(它自己就是权威),路由在 `server.py` 里按 path 顺序读。

旁边还有一份 `cleanup-plan.md`,那是一次全仓审查的**方案**,大部分已经执行完,
读它之前先看它顶部的执行状态,否则会照着去修已经修好的东西。
两份的分工:那份是「那一次要做什么」,这份是「以后每一次都不能破什么」。

---

## 一 · 这个仓在对抗什么

一句话:**它存在的理由是「坏了但看起来没坏」这一类失败。**

如果改动之后某个东西坏掉时页面仍然显示正常,那个改动就是失败的,哪怕功能上它工作。
反过来,一个功能不全但把「我没查」说清楚的面板,是合格的。

这一类失败有四种常见形状,**它们会在这个仓的任何一层复发**:

**「未检查」和「零」长得一样。** 一个没配路径的来源渲染成 0,和一个真的是 0 的来源
渲染成 0,读的人无从分辨。所有面板都必须把「有没有查成」和「查出了什么」分开报。

**被喂空的闸门打印绿色。** 一个断言全被跳过然后退 0 的检查,和一个真的全过的检查,
输出一模一样。判据是「退 0 **且** 报出的条数达到下限」,不是「退 0」。

**看着可点却不可点。** 一个能聚焦、能按下、按下去有成功提示、而实际什么都没变的控件。
这个仓里最近的一例:页面上能排链的顺序并保存,但一个环境变量压着它, 所以页面必须
主动说出「你改的当前不生效」,而不是报告一次成功。

**两份东西漂了。** 同一个事实写在两个地方,改了一处。漂了之后两份都还在正常渲染,
看不出哪份是对的。

## 二 · 不变量

改动时这些不能破。每一条后面是它的来历,不是空话。

### 缺失、零、坏掉,必须是三种不同的显示

不是两种。「我没查」「我查了是零」「我查了但出错了」要采取的行动完全不同,
所以它们不能共用一个画面。这条在代码里的体现遍布各处:`cheap_share` 在没有样本时
是 `None` 而不是 `0`;账本文件不存在时页面写「未检查」而不是画一排 0;
产物新鲜度有五个状态而不是两个。

**一个字段有默认值的时候尤其危险**, 默认值会把「没设」变成一个看起来正常的值。

### 闸门必须被证明可以失败,而且要有负对照

只投毒不够。投毒证明它**会**红,负对照证明它**不是**总是红(否则拦得准和拦太宽分不开)。
这个仓的测试里大量 docstring 记着「第一次投毒没红」的具体原因,那些是最值钱的部分。

**投毒本身也要验证**:先断言毒真的落进文件了,再看测试颜色。
失败的投毒和成功的防御,输出一模一样, 这个坑在这里犯过不止一次。

### 汇总层只搬结论,不重新判定

任务用它自己的判定键,产物用 freshness 的状态,仓库用 repos 的状态。
在汇总层另立一套「怎么算失败」等于把同一条规则写两遍,而两份规则漂了的时候,
两块内容都还在正常渲染。

汇总视图的验收判据是**逐来源对数**:总条数必须等于各来源自己报的条数之和,
并且逐来源分别对齐。「渲染出来了」不是验收。

⚠ **已知有一处没做到,别照着它学**:磁盘占用和记忆池那两组阈值,后端根本不判
(只下发百分比),于是前端在好几处各写了一份同样的阈值。这不是「两个地方各判一次」,
是「后端不判、前端多处各判一次」。要加新面板时按上面那条做:**判定放后端,
前端只画结论**。哪天有人去修存储那一块,方向是把阈值收回后端,不是再加一处。

### 能变成一份的就变成一份,变不成才上闸门

顺序是:能不能删掉第二份(让它派生出来)→ 必须存在但能不能生成 → 两份都得手写
**而且其中一份在这个仓之外** → 才上闸门。

**一个对账闸的存在,本身就是承认这里有两份。** 这个仓曾经有三个对账闸,
它们的 docstring 说的是同一句话的三种说法;现在只剩一个,
因为那一处的第二份是仓外的启动器,消灭不掉。

### 写方硬失败,读方可降级

读不到东西就干净地报「未初始化」并说清该配什么;写不进去必须抛,不许耸肩。
一个把真实观察扔掉的写方、或者「好心」退回别处写的写方,都是 bug。

### 公开仓里不许出现机主的私有标识

这是个公开仓。仓名、家目录下的约定路径、真实数据,一个都不能进。
`.pii-allow` 不是出口, 那个文件顶上写着机主自己的数据一条都不许加进去。

**判据是动态的**:同一段文字,在一个私有仓被创建并登记之后才成为泄漏。
所以问的不是「这串字符看着敏不敏感」,而是「它此刻指不指得到一个真实存在的私有东西」。

### 这个模块的对外返回都要能过 `json.dumps`

读侧模块的每个返回最终都进 HTTP 响应。这条有一道整类的闸盯着,
新加的函数自动进来, 不要改成逐个函数写用例,那只覆盖想到的那几个。

## 三 · 前端的坑

前端没有构建步骤:`console.html` 是外壳,脚本是 `static/` 下由 `static/app.js` 按序载入的
一组经典脚本,共享一个全局作用域。它的坑有一个共同点:
**看不出来,只能量出来。**

### 量 computed style,不要靠看

一次真实事故:明细表每行从 20px 变成 184px、整张表 9300px 高,
原因是行上写了 `class="row"`,撞上 Tabler 自己的栅格类 `.row{display:flex}`,
于是每个 `<tr>` 变成 flex 容器、九列竖着堆起来。**页面不报任何错,字一个不少,
只是排成了九行。** 真浏览器里量 `getComputedStyle(tr).display` 才看得出来。

现在有一道闸:Tabler 的布局类不许出现在 `<table>/<tr>/<td>/<th>` 上。
判据刻意收窄到表格元素, 页面另有十来个 Tabler 组件类在被正当使用,
不收窄就得配一张没人核的白名单,然后那道闸会被关掉。

### 两个 document 级 click 监听,先注册的先跑

`stopPropagation` 拦不住同一个元素上的另一个监听(那要 `stopImmediatePropagation`)。
新加的挂点如果和已有的 `[data-task]` / `[data-goto]` 这类选择器有重叠,
**必须放进先注册的那个监听里**,否则点击会被另一条接走, 实测表现是
「动作确实执行了,但人被弹到了另一屏」,看起来像按钮点错了地方。

### 能聚焦就必须能激活

给一个元素加 `tabindex="0"` 而不把它接进 Enter/空格处理器,
造出的是一个能用 Tab 停上去、按回车没反应的控件。那比根本停不上去更糟,
因为它**看起来**是可操作的。有一条测试钉着这条对应关系。

### Esc 只退一层,新的展开态要登记

页面没有快捷键。Esc 的分派在 `navigation.js` 的 `handleEscape`:对话框、弹出层和下拉菜单开着时不动,
焦点在能打字的框里时先清空再离开,其余按当前分区查 `ESC_STEPS`。新加一种「展开着、可以收起」的状态时,
在那张表里给它所在的分区加一步,并让那一步只在状态真的开着时返回 true;
不在表里的分区什么都不做,这样 Esc 不会去改一屏看不见的东西。逻辑放在 `navigation.js` 而不是 `events.js`,
是为了让 node:vm 台架能测到它(`tests/test_keyboard_conventions.py`)。

这一屏没有可退的层时,Esc 的最后一步是 `returnToOrigin()`:只有下钻来的屏才有来源,回去一次就用掉。
「下钻」由 `navigation.js` 的 `DRILL_TARGETS` 认(`data-task`、`data-goto` 等),`events.js` 在点击的捕获阶段调 `markDrill()`。
新加一种「跳到别的屏去看细节」的按钮,把它的属性加进 `DRILL_TARGETS`,否则目的屏不会有「← 返回」。
从侧栏进来要传 `showView(key, true, {reset:true})`,那样到达的屏没有来源。测试在 `tests/test_shell.py`。

### 外框:一个刷新、标签上的徽章

顶栏的刷新会把 `PAGE_READS[当前屏]` 全部重跑一遍,所以卡片上不要再加一个同样的刷新图标;
新面板的读取挂进 `PAGE_READS` 就有了刷新。只有比整页刷新便宜得多、而且只读一小块的,才单独给一个带字的按钮
(会话库的「重新扫描」是唯一的例子)。徽章用 `setBadge(视图, 数, 是否只是警告, 说明)`,
来源路径登记在 `BADGE_SOURCES`,补读的函数登记在 `BADGE_LOADERS`:「…」和「?」是靠这两张表和 `api()` 报上来的读取记录判断的,
漏登记的徽章会一直是「…」。

### 对话框、确认框和菜单

对话框一律用 `console-dialog` 外壳(`.dialog-head` 里标题加 ✕,`.dialog-body`,`.dialog-foot` 里次要按钮在前、主按钮在后),
标记上写 `closedby="any"`。点遮罩只交给浏览器的 `closedby`,不要写 `event.target===dialog` 的点击处理:
那种写法在输入框里拖选文字、松手落在遮罩上时也会关掉对话框。忙着和有人打了字的时候调 `actions.js` 的
`syncDialogDismiss(dialog, busy, dirty)`,它把 closedby 改成 none / closerequest,并让 ✕ 跟着取消一起灰掉。
有输入框的对话框包进 `<form method="dialog">`,主按钮 `type="submit"`,其余按钮一律写 `type="button"`:
表单里没写 type 的按钮默认是提交,排在前面的「取消」就成了 Enter 按到的那一个。提交处理先 `preventDefault()`,
再调原来的函数,函数开头照样核一遍条件。✕ 写 `data-dismiss="<取消按钮 id>"`,点它就是点那个取消。

要问一句「确定吗」用 `askConfirm({title, body, items, more, confirmLabel, danger})`,它返回 Promise<boolean>,
取消、Esc、点遮罩都是 false;危险的确认把焦点放在取消上。不要再用浏览器自带的 `confirm()` / `alert()`,
`tests/test_overlays.py` 会扫。结果要留给人核对的,写进页面上的状态行。

行内的「更多」菜单用 popover:按钮写 `popovertarget`,菜单写 `popover` 和 `.pop-menu`,位置由 CSS 的
`position-area` 贴在按钮下方。菜单的开合用 toggle 事件(捕获阶段)记下来,列表重画之后再 `showPopover()`;
菜单里的项被选中后先 `closeMenuFor(el)`,接下来弹出的对话框关掉时焦点才回得到「…」上。

### 不可用的按钮:一条样式,一个函数

按钮灰掉的样式只有 `styles.css` 末尾那一条 `button:disabled`,带 `!important`:变体规则(主按钮、危险按钮、
行内操作列、对话框提交)个个比它具体,以前就是它们把灰掉的按钮染回能点的样子。新写带颜色的变体或悬停规则时,
加上 `:not(:disabled)`;`tests/test_disabled_state.py` 会扫所有作用在按钮上的 `:hover` 规则。

灰掉一个按钮走 `api.js` 的 `setDisabled(button, reason)`(页面自己的原因走 `ConsoleActions.gate`,只读预览会压过它),
拼 HTML 时用 `disabledTitle(label, reason)` 或 `ibtn(sym, label, extra, cls, reason, hint)`。
提示一律是「动作名（不可用：原因）」,动作名只取一次(aria-label、`.control-label`、原 title 依次),重复同步不会叠后缀;
带字的按钮在标记里写 `data-label`,因为它的 title 会随状态变。只读不写的 POST(比如看 git status)给 `api()` 传 `inspect:true`,
它就不进「最近操作」、不锁全页。清除筛选按钮的亮灭由 `operations.js` 的 `syncResetFilters()` 统一算,
新加一个筛选范围时在 `RESET_FILTER_COUNTS` 和 `RESET_FILTER_SEARCH` 里各加一行。

### 四种状态、时间、数字、提示条:用 api.js 里的那一份

读取中、未检查、零、读取失败必须是四种样子。拼 HTML 时用 `loadingBlock(what)`、`emptyBlock(text,{filtered:'<筛选范围>'})`、
`errorBlock(what, error, retryAttr)` 和 `countCell(state, n, reason)`(state 取 loading / unchecked / broken / ok),
筛选计数用 `matchCount(n, m, unit)`。`errorBlock` 只把人话放进正文,`work_reader_failed` 这种代号和「说明 (代号)」里的括号只进 title。
时间用 `fmtTime(ts,{relative, now, soon})`,要悬停全称就用 `timeTag(ts)`;数字用 `fmtNum(n)`,字节用 `kb(n)`。
`tests/test_display_helpers.py` 钉着这些输出。

`toast(message, tone)` 的 tone 是 ok / info / warn / bad,不写就是 info。成功(读回来确认过的)写 'ok',
只是受理、还没确认的写 'info' 或 'warn',出错写 'bad'(它会一直留着)。操作面板的收起和 ✕ 在 `ConsoleActions`
(`collapseDelay`、`dismiss()`、`expand()`),测试见 `tests/test_operations_ui.py` 里用假定时器的那三条。

字号只有 `--fs-title` / `--fs-lead` / `--fs-body` / `--fs-meta` 四档(20/14/13/12),`--fs-chip` 只是 `--fs-meta` 的别名,
别再写死 px。新表头、新芯片加进 `workbench.css` 末尾那两条共用规则的选择器里,只在自己的规则里写颜色和描边。

### 死 CSS 和模板拼出来的类名

有一道闸扫「写了规则但页面上没有东西会匹配」的 CSS。由模板拼接产生的类名
(`d-${k}` 这种)要登记在豁免表里**并注明拼接点**,否则那张表会变成静默的免检名单。

### 「落在那一片」不是判据,判据得是一个等号

跳转/定位/对齐类的验证,必须写成「期望位置 == 实际位置」的等号,
不能写成「看起来落在那附近」。一次真实事故:点连续降级段跳到明细,
落点一直稳定地差几条,而段内每条记录长得都一样,所以目视完全看不出来。

## 四 · 后端的坑

### 两套编号并存时,名字必须各自说清自己是哪一套

账本里有「绝对物理行号」(含空行和坏行)和「列表下标」两套编号。
一个叫 `index` 的字段在这种场合说不清自己是什么, 现在它们分别叫 `_i` / `start_i`
和 `start_offset`。两个数在一个没有空行的账本上恰好相等,
所以**只用干净 fixture 的测试永远发现不了这件事**。

### 清掉环境变量不等于隔离

对**有默认落点**的变量,测试里必须 `setenv` 改道到临时目录,**不能 `delenv`**,
清掉它等于启用那个默认落点,而默认落点通常是真机上的真实文件。

这个坑在隔壁仓造成过一次真实污染:一个专为隔离而写的 fixture 把八百多条测试记录
写进了机主的真账本,全程绿色。判断一个变量属于哪一类只看一句:
**它没被设的时候,代码会去写什么地方?**

### 缓存键要跟着文件走,不要按时间过期

账本是只追加的,缓存键是 (路径, 字节数, mtime)。写成「缓存 N 秒」会让
一次刚发生的调用在页面上消失几秒,而「跑完了但看不见」正是这个仓要防的形态。

### 判据挑错字段,和没查一模一样

一次调查里拿 `provider` 字段去找测试产生的合成名字,得到 0 条,差点据此宣布干净,
那些记录的 `provider` 是 `null`,合成名字藏在 `chain` 字段里。
结论至少换一个判据复核一次。

**同一形状还有一次更贵的**:代码注释里写着「2026-09-08 核实,**没有任何计划任务在跑
摄入器**」,而核实方法是按名字去任务计划里找。真相是摄入有两条路径,高频那条是被
**另一个任务在内部调用**的, 按名字永远查不到。于是一条「我核实过,没有」的注释,
比它替换掉的那句错得更有底气,而且那句话还经 `/api` 下发到了页面上。
**一个关于机器配置的断言,从这个仓里说出去就成了对外契约的一部分,而这个仓看不见那台机器。**
现在那两处只写形状不写排班,要知道摄入新不新鲜看 `ingest_verdict`(它读数据自己的时间)。

### 扫描器漏掉一半输入时,和真的全都合规长得一样

给「每条 `/api/` 路由都必须查令牌」写通扫闸时,第一版正则只认 `path == "..."`,
于是 POST 那几条(写成 `self.path.split("?", 1)[0] != "/api/act"`,既有 `self.` 前缀
又是 `!=`)**整类没进扫描**, 包括这个服务器上唯一能改机器状态的那一条。
新写扫描器时,先打印它扫到了什么、数一数对不对,再信它的颜色。

## 五 · 反复出现的那几个

这些在这个仓里**各出现过三次以上**。复发说明它们不是手滑,是某种直觉在反复产生同一个错误。

### `except OSError: continue`(复发四次)

吞掉一个读不到的条目然后继续,于是「这个目录里没有东西」和「有东西但我读不了」
变成同一个空列表。**读不到要计数并报出来**,哪怕只是一个 `errors` 字段。

### `code in ("a", "b")` 这种松弛断言(复发三次)

一个动作上有好几道闸互相兜底,断言「返回码在这几个里面」等于放弃了「是哪一道拦的」。
放开其中一道,另一道仍然会挡,于是投毒**不会红**。每条用例钉死自己那一道。

### 一份规则两三份实现(复发六次)

调色板、返回码集合、PowerShell 解析器、参数闸……每一次都是「这里再写一遍更方便」。
处理顺序见前面那条不变量:先想能不能让第二份派生出来。

### 「我核实过,没有」而核实方法有盲区

按名字去找一个被别人内部调用的东西,永远找不到。
**一个带着核实日期的否定结论,比没有结论更容易被信。**

### 一个防 X 的判据,把 X 钉成了期望值

事件日志读完时会抛 259,而判据写的是 `"259" in str(e)`, 子串匹配,
于是一个消息里含 `record 12590` 的无关错误被判成「正常读完」,
结果是 `enabled=True`、`dropped=0`、条数偏小但看起来确定。
**那正是这个模块开头写着要防的那件事。** 更麻烦的是当时的用例把这个行为
断言成了期望,理由是「记录一个已知的过宽」。

要记录一个已知的洞,**写进 docstring,别写进断言**, 写进断言之后,
下一个人看到的是设计,不是欠债。(2026-09-15 已收紧为词边界匹配。)

### 会误报的闸门等于被关掉的闸门(复发七次)

这条和「宁可严一点」的直觉是反的。一道天天叫的闸,人会去放宽它或者绕过它,
然后连真的那一类一起放过。所以新写一道闸,除了投毒(证明它会红),
还要**把它该放行的形状也列一遍逐个跑**, 只投毒不列放行样本,
分不出「拦得准」和「拦太宽」。

## 六 · 两处已知的张力,不要顺手「统一」

### 同一个威胁,两个模块给出相反结论

对「一个联接指向树外」这件事:一处专门写了用例挡它,另一处**刻意不解析最后一段**、
明确放弃这道防护,因为那边的东西就是用目录联接部署的,解析掉会把合法路径判成越界。

两处都诚实,理由都写在各自的代码旁边。**但这是一个仓里的两套标准**,
而放弃防护的那一侧没有任何用例记录「真遇到会怎样」。
要动任何一侧之前,先读另一侧的理由。

### 一份拷贝被「降级」了,但没有消失

读侧有一个内置的链顺序常量,它的权威在另一个仓里。处理办法是把它降到最后一级
(只要账本里有过一条真实记录就以记录为准),并把徽章画成虚线灰、写明它是一份拷贝。

**这缓解了问题但没有消除它**:那份拷贝仍然在,只是现形条件被推到了
「一台从没调用过的全新机器」, 而那恰恰是最没人核对的场合。
知道这个边界在哪,比以为它已经解决了强。

## 七 · 加一个新面板要动哪些地方

按顺序。标星的是**漏了不会报错**的。

1. 后端读侧模块 `scripts/task_console/<name>.py`,纯读、不 import 被观察的那个仓。
   **库依赖不算被观察的仓**:`convo-chain`(对话链)、`llmcall`、`fleet_guards` 是
   `pyproject.toml` 里钉了版本的依赖,按固定名在进程内导入;被观察的生产者(reminder 的
   work-feed、SMITH 目录)只走它们的 CLI 或快照。判据是控制台借的是对方的**规则**(库),
   还是读的是对方的**产物**(生产者)。库不读 `TASK_CONSOLE_*`,根目录之类由路由显式传进去;
   它在 `integrations.py` 的 `ADAPTERS` 里是一行 `library` 层、没有 endpoint 的登记。
   那一行**不是健康检查**:`convo-chain` 在 server、convos、work_context 顶层导入,缺了控制台
   直接起不来,不会退化成一块面板不可用。所以真正的前置条件在安装阶段:运行时锁里没有它的
   wheel 行,就不能装由这个版本构建的 generation(它不在 PyPI 上,别的安装路径都解析不到)。
2. `server.py`:`import`、GET 路由、必要时 POST 路由与它的 `Refused` 处理
   (逻辑在库里的,接库自己带 `code` 的错误类型,比如对话链的 `ConvoChainError`)。
   **每条 `/api/` 分支都要 `_authed()`**, 这条现在有通扫闸盯着,漏了会红。
3. 前端是模块化的,不再是一个 `console.html` 里的大脚本:
   `static/panels/<name>.js` 一个文件,登记进 `static/app.js` 的 `CONSOLE_MODULES`
   (顺序即依赖顺序,`events.js` 永远最后),新样式表单开一个 `static/<name>.css`
   并在 `console.html` 里 `<link>`;两者都要进 `server.py` 的 `STATIC_FILES`,
   否则服务端 404(`test_panel_parity` 要求三处集合完全相等)。分区的名字在
   `static/navigation.js` 的 `VIEW_GROUPS`,首次读取挂在 `static/operations.js` 的 `PAGE_READS`。
   要标成 `OPTIONAL_PANELS` 的面板有三条硬要求:载入时不碰 DOM(只定义全局,挂点放进
   一个 `start<Name>()`,由 `events.js` 用 `typeof` 守卫调用);它的容器写死在静态 HTML 里,
   载入失败时 `app.js` 才有地方写「加载失败」;所有异步路径自己 catch,
   漏出去的 rejection 会点亮整页的「Console module failed」。别的模块调用它时一律 `typeof` 守卫,
   它没载入时调用方要退回原来的行为(会话行退回「复制路径」就是这么做的)。
   一个分区里的下钻用 `#<分区>/<参数>` 的地址:`showView` 只按第一个 `/` 切,
   参数交给面板自己的路由函数(`convoChainRoute` 是现成的例子)。
4. ★ 侧栏徽章:`setBadge()`,外加 `BADGE_SOURCES` / `BADGE_LOADERS` 两张表(见上面「外框」那一节)。
   不加的话这一屏「有事」时没人知道,而页面看起来很正常。
5. ★ 总清单 `renderTodo()` 里的对应项,如果这一屏会产出「要人管的事」。
6. ★ 新读的环境变量要同时进 `scripts/task_console/README.md` 的表**和**
   `selfcheck.py` 的 `SOURCES` 或 `OVERRIDES`, 那两处各有一条双向对账测试,
   漏了会红(这是好事:它是这个仓里少数几处「漏了会喊」的地方)。
   README 那张表里每一行都必须写明「不设会怎样」,这一条也有闸。
7. 测试:读侧模块的用例(带负对照)、服务端组装层的用例。
8. ★ 真浏览器跑一遍:量 `scrollHeight`、量关键元素的 `getComputedStyle`、
   窄窗口(约 400px)量有没有横向溢出。

带 ★ 的那几步,漏了不会有任何东西变红。会红的闸目前是五道:
`selfcheck` 的来源双向对账、README 环境变量表双向对账、历史两条通路的字段归类、
`subprocess` 必须钉 `stdin` 与 `creationflags`、页面脚本过 `node --check`;
加上这次新补的路由鉴权通扫,是六道。

## 八 · 看起来能改、其实不该改

- **不要给 model 加钉,不要加回 MODEL 对账。** 那是决定不是疏漏。
- **不要恢复「不用框架」。** 外壳是 vendored 的 Tabler,随仓发、不吊 CDN,
  这台控制台正是出事的时候要打开的,而出事的时候网络是最不该依赖的东西。
- **不要给这个仓加 `ARCHITECTURE.md` / `CONTRIBUTING.md` / `CHANGELOG.md`。**
  它们没有可对账的内容,落地就是几份会漂的散文。这份文档刻意只写不变量和事故,
  就是为了不变成那样。
- **不要在业务代码里留「找不到 submodule 就退回 `tools/` 那份」的 fallback。**
  实测过:一份陈旧拷贝在路径没改全的地方会赢过当前那份。
- **不要把「某一列在真实数据上是空的」当成这个字段没用。** 有些字段的价值只在
  下一次异常发生时兑现,而那种时候没有别的东西会说话。
- **动作表的路径闸里,`abspath` 不是 `realpath` 的笔误,末尾那一段也是刻意不解析的。**
  这台机器用目录联接部署,解析掉会让合法路径被判成越界。代价写在那段代码的 docstring 里,
  要改先读它。
- **`Refused`(以及 convo-chain 的 `ConvoChainError`)带 `code` 不是为了好看。** 一个动作上有好几道闸互相兜底,
  只断言「抛了异常」证明不了是哪一道抛的, 放开其中一道,另一道仍然会挡,
  于是两条测试在各自的投毒下都照样全绿。`code` 让每条用例钉住自己那道闸。
- **「有两份实现」不一定是错的,先读注释。** 这个仓里有几处刻意的重复,
  比如对外契约那一份带着 `authority` 字段自述它是谁;还有几处刻意**不合并**的两分
  (missing 与 unset、`_OUT` 与 `_DROP`)。合并它们会把两种要采取不同行动的情况
  变成一种。
